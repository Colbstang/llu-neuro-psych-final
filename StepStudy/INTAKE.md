# Screenshot question intake

`IntakeStore(db_path, image_dir, catalog_path=None, ocr=None)` stores screenshot records and content-addressed image copies in the caller's private app-data directory. Both database and image paths must resolve outside this repository. OCR uses the bundled macOS Vision helper; the first call compiles it to the system temporary directory. Tests and alternate deployments can inject `ocr(Path) -> str`.

`start_watch(folder=None)` snapshots existing image paths and starts a poll-controlled watcher. With no folder, it watches only `~/Desktop` files named `Screenshot…`, `Screen Shot…`, or `ScreenShot…`; a selected folder watches image files in that folder. It does not capture the display. The server owns the polling cadence and calls `poll_watch()`; `start_watch()` creates no thread. New files must be stable across two polls before OCR starts, and each poll OCRs at most two images. `stop_watch()` and `close()` stop tracking. `scan_folder(folder)` explicitly processes existing PNG/JPEG files, including files already present at startup, with a maximum batch of 20 images and explicit truncation status.

Primary methods: `list_questions(status=None, limit=100)`, `get_question(id)`, `search_questions(query, limit=50)`, `confirm(id, confirmed=True)`, `retry_question(id)`, `set_topics(id, topic_ids)`, `mark_outcome(id, outcome)`, `delete_question(id)`, `image_path(id)`, `topic_signals()`, `status()`, `start_watch`, `poll_watch`, `stop_watch`, and `scan_folder`. OCR failures stay visible in `row.error` and the aggregate `counts.error`; they have empty OCR text and cannot be confirmed until `retry_question(id)` succeeds. Retry updates the same private record and SHA-256 identity. `set_topics` accepts only known catalog IDs. `image_path(id)` accepts only an active stored question ID and returns its private copied image path, so an image endpoint need not accept arbitrary paths. The stored row API never includes source paths or private image filenames.

OCR text is preserved in full up to 200,000 characters. The parser marks a question confirmed only when it sees a question-like stem, at least two answer-option lines, and a clinical cue or taxonomy keyword; ordinary surveys are left for confirmation, and unrelated text is excluded. Topic IDs come only from whole-term keyword matches in `data/topics.json` until a user explicitly sets them. Outcomes start as `unknown` and change only after an explicit `mark_outcome` call; no answer is generated or graded. Deletion is soft and retains the private record.
